# 中医问诊 Agent

> 把一本 547 页的扫描版中医临床医案集 + 十六部古籍，做成**能查证的问诊 Agent**：
> 分层检索 + 多模型分工 + 交叉验证，**每一步判断都能追到原文**。

**它敢给方案** —— 定证、主方、药味与克数、煎服法，全落下来；
**关键是每一条都能被追查**：这个证凭什么定、这味药为什么要、这个克数从哪来。

- **不上向量库**（第一节）—— 中医证候是离散枚举，「苔厚腻」和「苔薄白」在向量空间里是近邻，**中医上是相反的证候**。拿它检索，命中的全是反的。
- **四层架构 + 模型分工**（第二、二·五节）—— 可枚举的走确定性查表，模型只用在"抽取 / 整理 / 判断"三处，**每一处用的模型不一样，理由也不一样**。
- **十五个关键决策，每个都有实测依据**（第三节）—— 含三次亲历翻车：自动归一化把反义词并成一个、一个过滤条件悄悄挡住 95% 的数据、体检检查本身返工三次。
- **边界写在明面上**（第八节）—— 它出的是**草案，医师复核后才用**；急危重症**必须同时提示立即送医**；库里全是成功案例，**学不出"什么时候会失败"**。

## 一、核心判断：不上向量库

主流做法是"什么都上 RAG"。**这个项目最关键的决策是反过来——主体不走向量检索。**

原因很具体：

> 中医证候是**离散枚举**（苔色 ∈ {白, 黄, 灰, 黑}、苔质 ∈ {薄, 厚, 腻, 腐, 剥}、脉 ∈ {浮, 沉, 迟, 数, 弦, 滑…}）。
>
> **「苔厚腻」和「苔薄白」在向量空间里是近邻**（都是"苔"、字面也像），**但中医上这是两个相反的证候**。
>
> 拿它做检索，命中的全是反的。

所以：

| 数据形态 | 走什么 |
|---|---|
| 离散枚举字段（症状 / 舌象 / 脉象 / 药味） | **精确匹配**（集合命中 + 加权） |
| 自由文本输入 | LLM 做**结构化抽取**（从受控词表里挑，不让它自由发挥） |

只看字面，「苔厚腻」和「苔薄白」确实"像"，向量检索看起来完全合理——**要避开这个坑，得先知道这两个证候在中医上是相反的。**

**这条判断的适用面后来变大了**：库里的**古籍原文层现在是 5701 块 / 610 万字**（素问·灵枢·伤寒·金匮·医宗金鉴·针灸大成…）—— 这个体量正是"该上向量库"的典型说辞。但实测：**首次查 0.27 秒（含把 5701 块读进内存），之后每次 0.11 秒**。几千块的语料，**上向量是纯负优化**（多一层 embedding 依赖、多一份要维护的索引、召回还不保证比字面准）。**"数据量够大就该上向量"这句话，缺了"多大才算大"这个前提。**

**但这个选择有它自己的坑，这一层必须自己补。** 全是实测踩出来的：

| 坑 | 例 | 不处理会怎样 |
|---|---|---|
| **词序** | 教科书写「脉浮」，词表归一后存的是「浮脉」 | 7 条判据里**每个脉象词都必然假漏检**，命中率凭空归零 |
| **否定前缀** | 「发热**不恶寒**」里能抠出「恶寒」 | **反义命中** —— 把禁忌当成了适应证 |
| **同义簇** | 「脖子僵」↔「项强」、「想睡」↔「但欲寐」 | 口语进不来，召回塌一半 |

所以匹配统一走**同一个同义词展开器**（`检索.py` 的 `展开()`），**不许各处自己写一个 `in`** —— 两处匹配器不一致，就会出现"面板说命中、脚本说没命中"。

## 二、架构：四层

```
① 结构层   药对 ↔ 证候映射表        ← 从书里的表格重建
② 规则层   四诊 → 方                ← 集合匹配，零模型
③ 判断层   模型（Jev / DeepSeek）    ← 只用在"泛化""抽取""整理"
④ 校准层   真实病例                  ← 靠临床数据积累，初始为空
```

**输入进来之后走这条链**（每步之间都可核对、可回退）：

```
自由文本 → ①抽取标签 → ②人工核对 → ③整理成规范陈述 → ④判断模型出候选
            (模型)      (表单里看/改)     (模型，只整理不添加)   (Jev + DeepSeek)
```

**原则：先定「哪些不该用模型」，再谈模型。**

凡可枚举的硬事实（剂量分布、配伍规则、证候标签）**一律走确定性查表**。
把确定性的事交给概率模型，是这类系统最贵的一类错误——**表不会胡说，模型会。**

**这四层里装的是这些东西**（数字会随处理进度变，看量级）：

| 层 | 内容 | 量级 |
|---|---|---|
| ① 结构 | 药对规则 / 受控因子表 | 105 条药对 · 241 个规范因子 |
| ① 结构 | 剂量分布（**按来源分行存，不合并**） | 236 味（问止 85 · 倪 151） |
| ② 规则 | 医案 / 处方 / 验方 | 1001 例 · 8312 行处方 · 156 首验方 |
| ② 规则 | 古籍原文块 | **5701 块 / 610 万字** |
| ③ 判断 | 本草条目（带 `可信度` 标记） | 524 条 |
| ④ 校准 | **自己的随访病例** | **0 —— 这是唯一会随接诊增长的部分** |

⚠️ **剂量为什么按来源分行**：两家的**单位不一样** —— 问止记**克**、倪海厦记**钱**。**数值放在一起没法比**（问止的"10"是 10 克，倪海厦的"10"是 10 钱 ≈ 37.5 克）。所以同一味药有几家就存几行，**每行自带单位**，调用方按来源分流。**换算只在人读的时候做，代码里绝不折算。**

## 二·五、模型分工（按「这层要什么」选，不是全用一个最强的）

这个项目同时用了 **4 个模型、5 个位置**，**每一处的选择理由都不一样**：

| 位置 | 干什么 | 用谁 | **为什么是它** |
|---|---|---|---|
| **抽取** | 自由文本 → 受控标签 | **`kimi-k3`**（阿里云百炼） | 原以为"抽取是抄录活，用最便宜的就够"。**实测把这个假设推翻了**：同一提示下 k3 输出 **201 token/例、6 秒**，而 flash 是 **4798 token/42 秒** —— **更贵的那个又快又省**（见下） |
| **整理** | 原话 + 标签 → 规范陈述 | **`deepseek-v4-pro`** | **它要吃医师原话**——要读懂"遇冷或吃凉的即腹泻"并把"遇冷即"这个前提**留住**，比改写标签难 |
| **判断①** | 这个方该不该用 | **`Jev`**（OpenRouter 的决策模型） | ⭐ **不是因为它最强，是因为只有它的输出形态对**——我要的是**概率**，不是一段读完不知道该信几分的文字 |
| **判断②** | 交叉验证第二判 | `deepseek-flash` | 要的是**独立第二意见**，不是第二强的模型 |
| **会诊** | 完整推演（流式） | **`kimi-k3`**（阿里云百炼 · 思考模式） | 这层要的是**推理深度**，不是"能流式就行"。而且思考档位是**量出来的**：`low` 只出 **734 字**思考、`high` **2216 字**、`max` **2350 字** —— **`high ≈ max`，「拉满」的天花板就在 high**，所以定在 high 不浪费钱 |

**两个关键取舍：**

1. **判断层不用通用大模型** —— 通用 LLM 只能让它自报置信度，而自报不可信（见决策 ③ 的实测）。**要概率，就得用一个原生输出概率的模型。**
2. **整理层敢用贵的** —— 这一层是"理解原话"，一旦在这里丢了信息（"遇冷即"被简化掉），**下游判断全建在有损的输入上**。这层省不得。

**最后一件值得单说：那个"便宜模型够用"的直觉，是被实测推翻的。**
抽取这层原以为是抄录活、用最便宜的 `flash` 就行 —— 实测 **k3 输出 201 token/例、6 秒；`flash` 是 4798 token/42 秒**。
**"贵模型更慢更费"并不一定成立**：思考模型的思考链**按输出计费**，它这条活**想得少，反而又省又快**。
所以"该强的强、该快得快"这句话，**前提是得先量过谁是快、谁是贵** —— 按价格表挑模型，这次会挑反。

## 三、十五个关键决策（每个都有实测依据）

### 1. 要概率，就换成"输出概率"的模型

通用 LLM 输出的是**文字**。想拿置信度只能让它自报——而自报不可信。

所以换用一个**原生输出概率**的决策模型（Jev），把"这个方该不该用"从"问一句话"变成"调一次可校准的概率查询"。

> 这是"按接口需求选工具"，不是"用最新最强的模型"。

### 2. 交叉验证不是加了就算，得先测它值不值

27 条真实病案（每条给 4 个候选方，其中 1 个是书上医生实际开的），两个独立模型各自判第一：

| 分组 | 条数 | 判对 | 准确率 |
|---|---|---|---|
| **两边选同一个方** | 16 | 14 | **88%** |
| **两边分歧** | 11 | 5 | **45%** |

据此把系统输出从"给一个答案"改成：

```
一致  →  高可信，直接用
分歧  →  标红「需人工复核」，两边都列出来
```

**它的价值是分出哪些该信，不是让自己更准。**

### 3. 置信度不能直接展示给用户

| 模型 | 自报分数档 | 实际命中 |
|---|---|---|
| 通用大模型 | 60~80 分（7 条） | **0%** |
| 通用大模型 | 80~100 分（17 条） | 94% |
| 决策模型 | 20~40%（18 条） | 61% |
| 决策模型 | 40~60%（7 条） | **100%** |

**通用模型中间档全是噪音**（典型的过度自信）；决策模型是单调的，但**系统性低估**。

→ **结论：排序可用，绝对概率必须先做校准才能展示。**

### 4. 自动归一化会把反义词并成一个（亲历翻车）

原始统计出 590 个标签，其中 **457 个只出现一次**（几乎全是形近字错字："舌有齿疯 / 齿症 / 齿瘦"都是"齿痕"）。

试过用**编辑距离自动聚类**，结果它把：

```
「舌苔白」 和「弦脉」     并成一个
「喜冷饮」 和「喜热饮」   并成一个   ← 反义！
```

**中文里差一个字常常是相反的意思**，而编辑距离只看"差几个字"。自动方案作废，改人工过一遍高频标签。

**顺带想通一步：不必清洗 OCR 输出，只要「受控词表」干净。**
模型是从词表里挑，不是从 OCR 文本里挑 —— 那些错字变体一个都不用管，归一化工作量直接砍掉一个数量级。

### 5. 文档工程的四个问题（都不是调参能解决的）

| # | 问题 | 解法 |
|---|---|---|
| ① | 相机水印烧进了每页图片底部 | 按行裁掉底部 8% |
| ② | 书页右侧栏被 OCR **按高度排序插进正文**，把句子割断 | **量出正文只到 80% 宽、侧栏从 91% 才开始**，取 86% 落在空白带里按坐标剔除 |
| ③ | 三列表格被读成流水文本，**列对应关系全丢** | **用第一列当"行钥匙"定行边界**，再重建列 |
| ④ | 200dpi 渲染 32×42 英寸的超大页，单页峰值 400MB，连跑 84 页把 13.9G 内存跑爆 | **先算后调**：源图原生只有 143dpi，200dpi 是在插值放大。降到 144dpi + 分批进程隔离 |

**关于 ③**：为什么用"第一列当行钥匙"而不是按行高切？因为**单元格会换行**（一行两行三行不等），按 y 切会把一个格子拆成两行。用第一列的位置定行边界，格内的多行自然归到同一行。

**关于 ④**：不是试出来的，是**算出来的** —— 5460 万像素 × 3 字节 = 164MB/张，加中间张量单页峰值 400~600MB。

### 6. 判断模型前面加一层"整理"（判断层不是直接吃标签的）

判断模型擅长判断、**不擅长整理**。给它一堆零散标签，它得先在自己脑子里拼出病机再判断——等于让它干不拿手的活。

所以前面加一层通用模型，把标签堆写成**规范的四诊陈述**：

```
进来：症状=心烦、夜尿、脚冷 │ 舌=舌瘦小、舌有齿痕、舌苔白 │ 脉=弦脉
出去：心烦，夜尿，足冷。舌体瘦小，舌有齿痕，苔白。脉弦。
```

**关键是锁死"只整理不添加"**——提示词里写死「不推断病机、不补症状、不下结论」。

> **它一旦在这层脑补，后面判的就是脑补出来的东西。** 这一层的纪律比它的效果更重要。

### 7. 抽取结果摊开给人核对，不藏着

模型抽完标签，**不直接拿去检索**，而是把抽到的**摊在表单里让医生核对**：对的不用动、多的取消、少的补勾。

```
抽取是「我替你想」
核对是「我把我的想法摊开你看对不对」
```

**这一步同时解决两件事：**

| 问题 | 怎么被解决 |
|---|---|
| 模型理解错了 | 你能看见——它把结果写在你眼前 |
| 你自己漏写了 | 那一栏空着，提醒你补 |

实测换种说法的能抽出来（"大便偏溏" → `大便溏`），**但抽漏也常见**——所以这一步不能省。

> 这本质上是把**可验证性**做进了交互：不让人只能"信或不信"，而是让人**看一眼、改一下**。

### 8. 明确的不做

| 不做 | 因为 |
|---|---|
| **不上向量库** | 见第一节，会算错方向 |
| **不上 GraphRAG** | 数据量还没到，建图成本换不来收益 |
| **不追大样本** | 先把手上这条流水线跑通再谈扩量 |

**每一步都写清"为什么不做"，避免用新技术掩盖没想清楚。**

### 9. 先问"能不能验"，再决定做什么

第二阶段本来想算"哪些因素对**疗效**有显著影响"。

**但书里全是精选成功案例——没有"没治好"的那一半，就没有会变化的结果变量（Y），谈"影响力"是空的。**

能算出来的只是**共现频率** P(因子|证)，不是**效应量**。这不是保守：

```
没有变化的结果，就没有"影响力"可言
```

所以把目标改成能立刻验证的那半：不预测，只回答"这个症状库里有没有像的案"。
**疗效权重只能靠接诊攒** —— 为此做了回访闭环（存病案 → 到期自动提醒填效果），这是唯一样本会"变"的来源。

### 10. 书里印着的判据，量过才知道不能用

拿书里现成的 **7 条六经判据**（"恶寒+脉浮+头项强痛 → 太阳"这种）去 951 案上量命中率：

| 判据 | 命中案数 |
|---|---|
| 恶寒+脉沉+精神萎靡 → 少阴 | 1 |
| 恶寒+脉浮+头项强痛 → 太阳 | **0** |
| 不恶寒反恶热+大汗大渴 → 阳明 | **0** |
| 往来寒热+口苦咽干目眩 → 少阳 | **0** |

**7 条里 5 条一条都命中不了。** 逐词拆开才发现**不是词表对不上**（"大汗大渴"命中 309 案、"脉浮"命中 112 案），**是"要求三个症状同时满足"这个用法错了**。

改用互信息单独衡量每个因子后，**数据自己算出来的判别因子跟教科书成分完全对上**：

| 经 | 数据算出来的判别因子 |
|---|---|
| 太阳 | 背痛、**脉浮** |
| 阳明 | 喜冷饮、口渴、小便黄 |
| 少阴 | **细脉、沉脉、弱脉、白天想睡**（对应"脉微细、但欲寐"） |

**成分是对的，错的是合取。** 教科书判据是"典型形态"的抽象，真实病案很少以完整形态出现。

### 11. 抽取结果必须标"原文说的"还是"模型推的"

让模型抽"六经"时**每条都标来源** —— 只有"原文自己说的"能当结果变量。
**拿模型推断的去验证"症状 → 六经"的规律，等于自己拟合自己。**

验证这个标记可信：**独立 grep 全文数出 189 例提到经名，模型标的"原文"187 条**，两个数几乎一致。

### 12. 静默失败最贵：一个过滤条件挡住了 951 例

排查时发现一个"按方名过滤"的载入条件**把 951 例病案全挡在检索之外**（那批病案方名本来就是空的）：

```
可检索病案： 965  →  50
```

**不报错、不报警，只是悄悄少一大半数据。** 顺着这条线又扫出同类三处 —— 其中一处"同 PDF 页码相近即判为同一患者复诊"的去重，**把 951 例并成 1 条**。

**共同点：全静默。** 现在载入层的过滤条件都要问一句"**谁真的需要它**"。

### 13. 静默失败的第二形态：不是"少给"，是"白给"

上面那条是**数据被过滤挡在检索外**。这一条是反面：**表建好了、数据也对，但活路径根本不读它。**

把踩过的每个坑写成一条可重跑的检查（`体检.py`），一跑就扫出 **9 张「有数据、但模型永远看不到」的表** —— 其中一张是**前一天刚补过的**（5701 块古籍原文）。
（当时 9 张；后来接掉 2 张，现在剩 7 张 —— 其中 5 张的内容**已经写进提示词**了，表本身不必读，属于**已知且有意**。）

**等于修了一条终点没人读的管道。** 数据是对的，但它到不了模型眼前。

还有一种更隐蔽的变体：**读半截**。

```
检索读的是 `剂量分布`（只有一家）
把两家并起来的**视图**     ← 没人读
```

**它不报错** —— 因为读的那张表**本身是好的**，只是**不完整**。"完全没读"和"读了一半"，症状一样安静。

### 14. 检查本身也会说谎，所以检查也得验

上面那条检查**返工了三次**：

| 写法 | 怎么坏的 |
|---|---|
| 纯字符串匹配（`表名 in 文件内容`） | **能被一句注释满足** —— 我在文档字符串里提了几个表名，那几个真没接线的表立刻被判成"读了" |
| 只认 SQL 关键词（`FROM` + 表名） | 反了 —— `_载附属()` 用的是 `"SELECT * FROM %s" % t`（**变量拼表名**），真在用的表被判成死的 |
| **按词法单元**剥掉注释与文档字符串 | ✔ 终版 |

**一个能被动满足的检查，等于没有检查。**

### 15. 同一份数据，在两张表里的门槛不一样

「倪案剂量分布」是垃圾堆 —— **347 味里大半是整句被当成药名**（"重用桔梗""患者较娇小故用""所以可以加重到"），根因是上游 **7787 行处方从没归一过**。修的时候划了条线：

| 表的角色 | 门槛 | 为什么 |
|---|---|---|
| **原始表**（处方） | **留痕** —— 认不出的原样留着，另存一列可回溯 | 它是**证据**，不是结论 |
| **派生统计表**（剂量分布） | **必须干净** —— 认不出就不写，宁缺勿猜 | 模型直接读它，留一条垃圾它就会原样引用 |

改映射时还踩到**两个反向坑**：剥连接词会把「合欢皮」剥成「欢皮」（合欢皮是正经药名）；拒绝用的字符类里加了个「药」字，把「乌药」也拒了（一次丢 86 行）。**过滤规则天然误伤合法值 —— 原样要先过一遍白名单，剥词是兜底、不是首选。**

结果：346 味 → 151 味，逐味人工过。

## 四、流水线

`吃书.py` 一条命令跑完从扫描件到入库的全程：

```
① OCR 全部页         裁底部水印 + 剔右侧栏（本地 RapidOCR，零上传）
② 抽医案             四诊 → 方名 → 药味剂量    入 医案/处方 表
③ 重建表格           药对表 + 单味药表
④ 抽体质分析         体质 ← 症状（书里每则医案都有这一段）
⑤ 抽加减/方性/结构符合方
⑥ 更新受控词表
⑦ 出报告
```

**工程细节**：断点续跑（认过的页自动跳过）、幂等入库（重跑先清本书数据）、多本书共用同一套归一规则表。

## 六、跑起来

```bash
pip install -r requirements.txt
```

|---|---|---|
| **判断层**（Jev + DeepSeek） | **必须** | 交叉验证靠的是两个**独立**判断，缺一个就没有"一致→高可信 / 分歧→标红"那套了 |

## 八、这套东西的边界

**它不是"AI 自己看病"。准确定位是「AI 出方案、医师复核」。**

| | |
|---|---|
| **它会做的** | 四诊结构化 → **定证型** → **给主方** → **给药味与克数** → **给煎服法**。每一步的依据都摊开（命中药对 / 古籍原文 / 相似病案 / 该药在本库的实测剂量） |
| **它不做的是"把话推回去"** | 提示词里明确**给了处方权**：不许写"建议咨询专业医师"这种句子 —— **那样等于没说**。证型、主方、克数、煎法**都要落下来** |
| **人工核对在哪** | AI 出的是**草案**，医师复核后才用。所以系统要做的不是"替人决定"，而是**把判断摊开到能被挑错**：每条标依据强度、标"原文说的"还是"模型推的"、标哪里拿不准 |

**「安全规则」管的是"怎么开得不出事"，不是"不许开"。** 库里 6 条：

```
炙甘草监制附子   生附子必须久煎   中病即止   瞑眩反应   急症送医   不替患者开方
```

⚠️ 最后那条 `不替患者开方` 与「有处方权」**正面冲突**，所以**代码里被显式排除、不注入提示词**
（`安全规则文本(排除=("不替患者开方",))`）。**同一张表里有一条自相矛盾时，处理方式是点名排除它，不是把整张表丢掉。**

**真边界（这几条改不了）：**

- **急危重症另算**：心衰 / 休克 / 中风昏迷 / 大出血这类，方案**必须同时提示立即送医** —— 方案不替代急救
- **数据边界**：库里全是**精选的成功案例**，**缺失败样本** → 不能用它预测疗效
- **统计边界**：第二阶段算出的因子判别力是**描述**，不是**预测** —— 结果变量（**原文自己写了六经的**）只有 **154 案**，按经分完是 阳明 65 / 少阴 54 / 太阳 30 / 少阳 22 / 厥阴 8、**太阴 0**；而且因子就是从同一批案子里抽的，**拿它自评等于同一份数据出题又答题**。所以那份报告里的数字**是"库长什么样"，不是"该开哪个方"**。⚠️ **太阴是 0 —— 这一经的结论完全没有证据，别当它被算过。**
- **另一个项目不是这个姿态**：面向**患者**的问答是另一个产品，那边是"不甩方子、重证只劝就医"。**两个姿态是故意不同的** —— 这个仓库面向**医师 / 专业使用者**，所以它敢定证、敢给克数。

> 一个只有成功案例的库，学不出"什么时候会失败"。
